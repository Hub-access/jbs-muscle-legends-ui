## 同一来源怎样更新两处

当前 `LocalPlayer.Character` → 一次安全复制与清理 → 带版本的规范化外观 → 正面独立副本 / 背面独立副本。第二份从已经清理好的第一份复制，不再读取一次 Character；没有常驻第三套完整模板。

正面相机在规范化角色的 −Z，背面在 +Z；模型没有镜像，也不跟随玩家跑步、转身或动作。背面单独按可见身体、重要配饰、宽高比和视场角取景，适度裁掉下肢；未读取展示相机 ViewportSize。两处使用相同的温和 Ambient/LightColor，各自调整 LightDirection，ImageColor3 保持白色，不改玩家实际肤色/穿搭。

刷新令牌同时包含角色代次、请求序号和外观修订。先准备所有可见展示区的新模型，再进行不 yield 的短提交；只有两处挂载成功才发布新版本并回收旧组。一处准备或提交失败，销毁候选并恢复旧组；旧组带“更新中/更新失败”标识。失效控件无法恢复时释放整组；重试有上限。过期结果只销毁。

角色未就绪时，统一通过当前玩家 UserId 查询账号备用；两处标明“账号备用”，不宣称是游戏体型。当前 Character 就绪后统一切回。隐藏/销毁取消订阅和定时任务；不可取消的引擎请求返回后由代理销毁过期模型。离开首页仅释放正面，侧栏可继续更新；滚动使横幅完全离开裁切区域时也暂停正面。恢复时重建最新版本，不复活旧副本。

正常首页稳定期两套 Model / WorldModel / Camera；只显示一处时一套；全隐藏时零套。外观监听仍保留有限的属性集合以记录脏状态，隐藏期无模型重建、账号新查询或定时重试。没有新增永久 RenderStepped、人物旋转或跟随动作。展示加载状态与脚本业务状态分离，不触发开始/停止、训练或重生。

现有适配边界仍在：超大异常部件会排除并标记；二维 BillboardGui/SurfaceGui 标签不转成三维配饰；自定义肌肉连接、WrapLayer 和服装贴合效果须用真实模型确认。规范化静态姿势不等于任意自定义骨骼均已兼容。

## 原生入口与验收步骤（待执行）

1. 在 **Roblox Studio** 打开 `JBS_Reference05.rbxlx`。正式入口在 `StarterPlayer > StarterPlayerScripts > JBS_Reference05 > Bootstrap`，依赖同目录模块；不依赖外部 UI 库。也可导入 `.rbxmx` 并把 `tests/NativeDualAvatarQA.client.lua` 作为同级 LocalScript 放入 StarterPlayerScripts。不要同时启用两种 NativeAvatarQA。
2. 先保持 QA 禁用，按 **Play**（不是仅 Run），观察主横幅右侧正面和侧栏左下角背面。两处状态版本相同、来源为当前角色；空资源 ID 时底图显示待上传。填入图片 ID 后分别确认加载与视觉完整性。
3. 在空白本地 QA 场景，停止 Play，启用 `NativeDualAvatarQA`。默认正式界面会被测试入口短暂接管，测试用 Tasks 为空；结束后恢复正式入口及原会话状态。请先使用正常窗口（建议 1672×941），确保两处展示区实际可见；运行期间不要更换真实人物，避免混淆30次重复计数。
4. 查看 **Output** 中的 `JBS_NATIVE_DUAL_AVATAR_QA` JSON。入口检查真实当前 Character 的安全复制、独立正背面、30次显隐、蓝色 R6/金色 R15 测试外观、迟到高头饰、独立尺寸取景、账号备用测试替身、部分准备/提交失败和销毁后晚到模型。测试外观不冒充第二个真实账号。自动失败时 `passed=false` 保留错误，不能把仅编译成功写成通过。
5. 输出记录无人物/仅正面/正背面/隐藏各180帧的帧间隔、模型与连接诊断。补记设备、系统、窗口分辨率、画质、场景；这些是 Studio 整体帧间隔，包含场景工作，不能称为 UI 独占 GPU 耗时。UI 展示代码本身没有逐帧追踪任务。
6. 停止测试、重新禁用 QA 后做人工验收：正常与较窄窗口（例如1280×800）全图、正背面局部；高帽/宽肩/大小体型/分层衣服；真实重生；第二个真实账号；图片无权限/失败；关闭后重开与销毁重建。观察头部不截断、肩背不拉伸、JBS和标语不挡人物。保留截图及两处版本与来源。
7. 回归导航、输入、开关、开始/停止与热键。该包现有未接入业务不能冒充真实训练；最终仍须用用户有权测试的目标工程与原业务绑定验证。QA场景通过不代表目标游戏或其他运行方式兼容。
